## 3. 修复的缺陷（代码改动）

**现象**：新建「图片转可编辑」项目 → 立刻转换 → `400 转换页面或当前版本记录缺失`，**必须重启服务才能转**。

**根因**（`server/app/pipeline.py:569`）：

```python
if ... or any(not r.get('current_version_id') for r in source_rows):
    raise ValueError('转换页面或当前版本记录缺失')
```

「转可编辑」要求每页有 `current_version_id`，该字段只由 `slide_versions.preserve()` 写入 —— 而它只被**生成**流程（`pipeline.py:429`）调用。`/import-pages` 用 `db.insert("slides", ...)` 直接建页，**不建版本**；`slide_versions.backfill()` 又只在**服务启动时**跑（`main.py:33`）。

**证据**：导入后 `current_version_id` 为 **0/8**；重启后 `backfill()` 补成 **8/8**。

**修复**：在 `import_pages` 的 `register_slides()` 之后立即调用 `pipeline.slide_versions.backfill()`，导入即登记版本。

**回滚**：删除 `server/app/main.py` 中 `import_pages` 里那句 `pipeline.slide_versions.backfill()` 及其上方三行注释即可（无 schema 变更、无数据迁移）。

### 3.2 缺陷②：导入项目看不到「原稿缩略图」

**现象**：`图片转可编辑` 建的项目，在「页面确认」步骤只显示「**原稿缩略图暂不可用**」，`/api/projects/{pid}/source-pages` 返回 `{page_count:0, ready:false}` —— 尽管 `data/files/<pid>/pages/pNN.png` 确实存在且 HTTP 200 可取。

**根因**：原稿缩略图由 `source_pages` 模块从上传的原稿（LibreOffice 转图）构建，`/source-pages/build` 端点会触发它；但 `import-pages` 只登记 slides，**从不触发缩略图构建**。

**修复**：`import_pages` 里 `source_pages.start(pid, saved[0])` + `asyncio.create_task(source_pages.build_background(...))`。该模块按设计「任何失败只写状态文件，绝不影响原稿解析或后续生成」，风险低。

**回滚**：删除该 `if source_pages.start(...)` 两行及其注释。

> 这项修复需要重启服务才对**新导入**生效；历史项目需重新导入或重启后由其他路径补齐。
